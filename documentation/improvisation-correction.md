# 即兴音符智能校正算法

实现位置：`src/features/chart/improvisationCorrection.ts`。保存入口为 `correctImprovisedNotes`，使用当前谱面的 BPM、偏移与 BPM 变化做网格校正。

## 目标与拍长约定

优先把即兴敲击整理到 **1/4 拍**网格；遇到更密集的段落，允许使用 **1/8、1/16 拍**。判断同时参考敲击密度、到网格的距离和相邻音符间隔，尽量保留演奏节奏与音符数量。

这里的“一拍”是 BPM 对应的一个节拍，分数表示这一拍的几分之一，并非四分音符、八分音符的命名。

以 120 BPM 为例：

| 网格 | 每格拍长 | 每格时间 |
| --- | --- | --- |
| 1/4 拍 | 0.25 拍 | 125 ms |
| 1/8 拍 | 0.125 拍 | 62.5 ms |
| 1/16 拍 | 0.0625 拍 | 31.25 ms |

这是一套确定性的节拍量化算法，不需要联网或模型推理。

## 保存流程

1. 演奏期间保留原始敲击时间，反向音符也按原始时间显示。
2. 点击“保存到制谱器”后，在内存中，按当前谱面的节拍网格计算校正结果。
3. **使用校正后的位置检查与原谱面的冲突**，包括同轨长按的覆盖区间。即使原始敲击没有重叠，吸附后重叠也会询问。
4. 没有冲突时直接合并；有冲突时按用户选择覆盖，或保留原音符并跳过冲突的新音符。
5. 校正和合并作为一次编辑提交，再写入谱面库。一次撤销会恢复保存前的谱面。

因此用户看到保存成功时，谱面库中已经是校正后的内容，不会先写入一版原始时间再进行第二次修改。取消保存不会改变谱面；确认覆盖时复用同一份校正结果；写入失败后的重试也不会重复校正或产生额外撤销步骤。选择继续演奏后，再次保存会根据最新敲击重新计算。

## 时间坐标与动态偏移

录制时的 `audio.currentTime` 与谱面音符的 `time` 都是音频绝对时间，单位为毫秒。谱面 `offset` 定义节拍网格的原点，不是一个应再次从录制时间中扣除的设备延迟值。

保存流程为：

```text
原始敲击时间 → beatAtTime(当前谱面) → 智能选择目标节拍 → timeAtBeat(当前谱面)
```

固定 BPM 时，转换关系为：

```text
原始节拍 = (原始敲击时间 - offset) × BPM / 60000
保存时间 = 目标节拍 × 60000 / BPM + offset
```

偏移在坐标转换中减去，并在返回音频绝对时间时加回。不在转换之前额外执行 `敲击时间 - offset`，也不在转换之后再次加减偏移。

例如，120 BPM、offset 为 +180ms 时，第二拍的时间为 1180ms，敲击记录为 1184ms，应吸附到 1180ms。如果 offset 为 -140ms，对应位置是 860ms，敲击 864ms 应吸附到 860ms。每份谱面使用自己的配置，不写死任何偏移量。

一个关键回归场景是 BPM 为 60000/360、offset 为 180ms：偏移恰好是半拍。第二拍的时间为 900ms，敲击 904ms 应保存为 900ms；若额外减去 180ms，则会错误地保存为 720ms，刚好提前半拍。

已有的 `shiftChartOffset` 在调整偏移时已经整体移动了原音符、BPM 变化与特效。即兴保存沿用同一绝对时间坐标，不再整体移动这些内容。原始敲击缓存保持不变；冲突确认和保存失败重试复用校正结果，避免重复处理。

候选位移范围和密度计算均直接基于原始录制时间。设备输出延迟与歌曲节拍原点是不同的概念，当前算法不会将谱面偏移另作设备延迟扣除。

## 第一步：转换为节拍坐标

先将录制的毫秒时间通过 `beatAtTime` 转成节拍位置。固定 BPM 时，可理解为：

```text
节拍位置 = (原始敲击时间 - 谱面偏移) × BPM / 60000
```

存在 BPM 变化时，复用项目已有的 tempo map，逐段累积节拍，最后扣除偏移位置对应的节拍数。计算完成后用 `timeAtBeat` 转回毫秒。

这样网格会遵循当前谱面的 BPM、BPM 变化和 offset，不会在变速处继续使用旧的毫秒间隔。视觉滚动速度特效不参与节拍计算。

## 第二步：识别近同时的和弦

先按时间排序。相邻敲击满足以下全部条件时，作为一个起音组：

- 与组内第一个音符相距不超过 **25 ms**。
- 与组内第一个音符相距不超过 **0.04 拍**。
- 组内没有同轨音符。

起音组使用成员的平均节拍位置，校正成功后整组对齐到同一网格线。这可以修正双押、三押时手指的轻微先后差，也避免把一次四押误算成四个极密集的起音。

始终以第一个成员作为分组边界，防止多个“彼此很近”的敲击连锁组成很长的和弦。同轨连续敲击始终作为独立起音保留。

## 第三步：估计局部密度

对每个起音组，计算它到前后相邻起音组的节拍间隔，取较小值 `gap`。没有邻居时使用无穷大。

| 最近起音间隔 | 密度偏好 | 细网格惩罚基数 p |
| --- | --- | --- |
| gap ≥ 0.18 拍 | 优先 1/4 拍 | 0.10 |
| 0.09 ≤ gap < 0.18 拍 | 倾向 1/8 拍 | 0.04 |
| gap < 0.09 拍 | 倾向 1/16 拍 | 0.02 |

阈值保留了一定的手敲误差余量：例如 1/8 拍的目标间隔是 0.125 拍，不要求用户恰好敲出这个数字才能识别。

密度只改变选择细网格的代价，**不强制整段使用一种网格**。一段 1/16 拍连打中的整拍和 1/4 拍位置仍然有效；远处的稀疏段落也不会被整份录制的平均密度拖到细网格。

## 第四步：生成候选网格线

以起音组的平均节拍位置为中心，查找 **前后各 1/8 拍**内的所有 1/16 拍网格线。

三个网格是包含关系，因此可以用网格编号 `tick` 分类：

- `tick` 能被 4 整除：属于 1/4 拍，细化等级为 0。
- 否则能被 2 整除：属于 1/8 拍，细化等级为 1。
- 其余：属于 1/16 拍，细化等级为 2。

每组通常最多有 5 个网格候选。还会增加一个“保留原始时间”的候选，供网格容不下的极密集敲击使用。

候选必须位于音频有效时间内。越界的网格会被移除，不能直接截到 0 或音频结尾，因为截断位置未必是真正的节拍线。

位移限制针对起音组中心；和弦成员相对中心还可能有最多 0.04 拍的原始差异。这个限制用来避免为了追求整齐，把音符拖到很远的位置。

## 第五步：给候选打分

令原起音位置为 `b`，候选位置为 `q`，细化等级为 `level`：

```text
位置代价 = [4 × (q - b)]²
细化代价 = level × p
单个候选代价 = 位置代价 + 细化代价
```

乘以 4 是以 1/4 拍作为误差单位。平方代价会惩罚较大的移动。1/4 拍位置没有细化代价，因此轻微早敲、晚敲通常会被拉回粗网格，而不是只寻找最近的 1/16 拍线。

当起音更密集时，`p` 会降低，允许使用细网格。即使是稀疏片段，如果音符明显更符合 1/8 拍位置，也允许选择 1/8 拍，而不会僵硬地拉回 1/4 拍。

“保留原始时间”候选的单个代价固定为 **4**，通常高于合法网格方案。只有在节奏、顺序和位移限制难以同时满足时才会选中。

## 第六步：动态规划选择整个序列

不逐个独立四舍五入，而是把每个起音组的候选作为一层，选择总代价最低的一条路径：

```text
间隔误差 = (当前候选 - 上一候选) - (当前原位置 - 上一原位置)
转移代价 = 0.35 × [4 × 间隔误差]²

当前累计代价 = 上一累计代价 + 当前候选代价 + 转移代价
```

转移时还必须满足：

- 不同起音组保持时间先后，不能交换顺序。
- 不同起音组不能被量化到同一位置，避免两次敲击被挤成一次。
- 若保留原始和弦时间，顺序判断使用组内最早和最晚的实际时间，防止相邻校正音符插入和弦内部。

输入中已经存在完全相同时间的重复敲击时，允许原始时间候选保留这种重复。算法不通过删除音符来掩盖输入本身的重复。

最后从最低代价的末尾候选回溯，得到每组最终位置，再恢复音符 ID、轨道和类型。

## 示例

下面使用 120 BPM、offset 为 0 的谱面：

| 原始敲击时间（ms） | 校正后（ms） | 解释 |
| --- | --- | --- |
| 1008、1523、1990、2517 | 1000、1500、2000、2500 | 稀疏敲击优先粗网格 |
| 505、558.5、631、684.5 | 500、562.5、625、687.5 | 约 1/8 拍间隔，保留细分节奏 |
| 502、529.25、565.5、592.75 | 500、531.25、562.5、593.75 | 更密集的 1/16 拍连打 |

## 保护措施与当前范围

- 不删除即兴音符，不改变 ID 和轨道，不修改输入数组。覆盖流程中用户选择跳过的冲突音符另行处理。
- 正常输出对齐到 1/4、1/8 或 1/16 拍，且符合位移和顺序限制。
- 对超过 1/16 拍网格容量的极短连打，必要时保留部分原始敲击时间；优先保留敲击数量，不强制拉远或合并。
- 只处理本次录制的普通敲击。已有谱面音符不会被一起重新量化；传入的长按音符也保持原样。
- 依赖谱面 BPM 和 offset 的准确性，不自动修正整个歌曲的节拍信息，也不估算设备的全局输入延迟。
- 当前候选仅覆盖上述二进制细分，没有三连音、五连音和摇摆节奏模型。此类演奏可能被整理为邻近二进制网格，需要人工复核。
- 原始录制只在本次会话缓存；保存后不会另存一份原始 take。撤销恢复的是保存前的谱面。

## 性能与验证

设起音组数量为 N。每组最多约 6 个候选，动态规划的每层转移是常数规模，因此主体时间和内存复杂度均为 **O(N)**。加上输入排序，整体时间复杂度为 **O(N log N)**。只在确认保存时计算，不在每次敲击或动画帧内执行，也不增加录制时的持久化频率。

自动化测试位于：

- `src/tests/improvisation-correction.test.ts`：各档密度、稀疏偏好、混合片段、和弦、极密集连打、重复时间、BPM 变化、动态正负偏移网格与半拍提前回归、音频边界与原始输入保护。
- `src/tests/improvisation-playtest.test.tsx`：保存前校正、校正后的冲突确认、重试不重复偏移等交互。

参数是当前实现的启发式取值，可根据真实演奏样本调整。优先调节密度阈值、细网格惩罚和间隔权重；始终保留数量、顺序与位移保护。
